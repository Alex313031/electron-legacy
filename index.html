Node headers for Electron for Legacy Windows

Serves npm_config_disturl so native modules can be rebuilt against this fork.

Release zips are attached to the GitHub releases, but node-gyp needs a directory tree rather than flat release assets — it asks for paths like win-x64/node.lib underneath the dist URL. That is what this site is for, and the only reason it exists.

Usage

npm config set disturl https://alex313031.github.io/electron-legacy/headers

or per-invocation:

npm_config_disturl=https://alex313031.github.io/electron-legacy/headers \
  npm rebuild --runtime=electron --target=44.10.2 --arch=x64

What node-gyp fetches

PathPurpose
v<version>/node-v<version>-headers.tar.gzheaders
v<version>/SHASUMS256.txtverifies the above
v<version>/win-x64/node.lib64-bit import library
v<version>/win-x86/node.lib32-bit import library

Only those four per version. The iojs-* aliases and the legacy x64/ and root node.lib locations that upstream still publishes are deliberately absent: node-gyp only ever requests them for targets whose major version is 1–3, which this fork will never be.
