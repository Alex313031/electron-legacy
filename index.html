Node headers for Electron for Legacy Windows

Serves npm_config_disturl so native modules can be rebuilt against this fork.

Release zips are attached to the GitHub releases, but node-gyp needs a directory tree rather than flat release assets — it asks for paths like win-x64/node.lib underneath the dist URL. That is what this site is for, and the only reason it exists.

Usage

npm config set disturl https://thorium.rocks/electron-legacy/headers

or per-invocation:

npm_config_disturl=https://thorium.rocks/electron-legacy/headers \
  npm rebuild --runtime=electron --target=44.10.2 --arch=x64

Those four per version, linked individually because directory URLs such as headers/v44.10.2/ return 404 — this site ships .nojekyll and GitHub Pages generates no directory listings. node-gyp only ever requests files, so that costs nothing.

The iojs-* aliases and the legacy x64/ and root node.lib locations that upstream still publishes are deliberately absent. node-gyp only names those for targets whose major version is 1–3 (isNamedForLegacyIojs in process-release.js), which this fork will never be — they were an Electron 3-era compatibility hack. Dropping them takes each version from 9.0 MB to 2.9 MB.
